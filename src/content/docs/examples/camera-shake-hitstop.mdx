Two things that make a game feel solid: a camera that moves well, and hits you can feel. This page
sets up a **Camera** that follows the player by itself (its **Target**: a look-ahead, an offset,
limits at the level's edges, no code), a small **CameraRig** script that zooms out while a button
is held, and a `Hit_Feel` procedure any script can call when something gets hit: a camera shake
plus a **hitstop**, the few frames of freeze that make a blow land. They're based on the demo
(`scripts/hero.odin`, `scripts/effects.odin`), whose levels' Camera nodes follow the hero this way.

## The scene

<Steps>

1. A **Camera** node anywhere in the scene, not inside the player (the first Camera of a scene is
   its camera, `scene.camera`). In the inspector's **Follow** group:
   - **Target**: the player (a CharacterMover, like the
     [platformer character](/examples/platformer-character/))
   - **Follow mode**: SmoothDamp, **Smooth time** 0.25
   - **Aim offset Y**: -24 (aim a little above the player's feet)
   - **Look ahead X**: 80, **Look ease**: 3
2. Its **Limits**: tick Left, Top, Right and Bottom, and type the level's edges (0, 0, 2560, 720).
   Its **Shake**: size 4, time 0.25 (what a heavy hit uses below).
3. The player gets `CameraRig` as another script (**Add script** in the inspector), for zooming
   out.
4. Project Settings > **Input**: an action **look** (Tab, the gamepad's North button).

</Steps>

## The scripts

```odin title="scripts/camera_rig.odin"
package scripts

import e "engine:."
import sdl "vendor:sdl3"

/*
CameraRig: on the player. The scene's camera follows the player by itself (its Target); this
zooms it out while "look" is held, to see more of the level.
*/
CameraRig :: struct {
	using script: e.Script,
	zoomedOut: f32 `export:"default=0.6 min=0.1 max=1"`,
}

@(init)
register_CameraRig :: proc "contextless" () {
	e.Script_Register(CameraRig, {
		update = proc(self: ^CameraRig, _: []sdl.Event, deltaTime: f64) {
			camera := self.scene.camera
			if camera == nil do return
			// Eased over a third of a second
			if e.Input_IsActionJustPressed(ACTION_LOOK) do e.Camera2D_ZoomTo(camera, self.zoomedOut, 0.35)
			if e.Input_IsActionJustReleased(ACTION_LOOK) do e.Camera2D_ZoomTo(camera, 1, 0.35)
		},
	})
}
```

```odin title="scripts/hit_feel.odin"
package scripts

import e "engine:."

// How hard a hit feels
HitWeight :: enum {
	// A light blow (the player's sword on an enemy)
	Light,
	// A defeat
	Heavy,
	// The player hurt
	Hurt,
}

/*
A hitstop and a camera shake for a hit. The hitstop freezes the game for a few frames (scenes and
globals update with a delta time of 0: physics, animations, particles and timers stop) while the
shake goes on, so the frozen frame shakes.
*/
Hit_Feel :: proc(scene: ^e.Scene, weight: HitWeight) {
	switch weight {
	case .Light:
		e.Game_HitStop(scene.game, 0.06)
		e.Camera2D_Shake(scene.camera, 2.5, 0.15)
	case .Heavy:
		e.Game_HitStop(scene.game, 0.09)
		// No strength or duration: the camera's Shake settings (4 px, 0.25 s)
		e.Camera2D_Shake(scene.camera)
	case .Hurt:
		e.Game_HitStop(scene.game, 0.12)
		e.Camera2D_Shake(scene.camera, 6, 0.3)
	}
}
```

Call it wherever a hit happens, for example in an enemy's hurt procedure:

```odin
// Given: self: ^e.Script, defeated: bool
Hit_Feel(self.scene, defeated ? .Heavy : .Light)
```

## How it works

- **The camera's Target** makes it follow that node by itself, after every node has moved each
  frame, with its follow settings (`camera.follow`): it starts on the target, then eases after it
  (SmoothDamp: a spring that never overshoots). A camera placed inside the player follows it
  rigidly instead, with no easing, look-ahead or limits.
- **The look-ahead** shifts the camera up to 80 pixels in the direction the player moves, so they
  see more of where they're going, and back to the middle when they stop; **Look ease** swings it
  over smoothly when they turn around. **Aim offset** moves the point it aims at.
- **Limits** keep the view inside the level: at its edges the camera stops and the player walks
  toward the screen's edge, whatever the zoom. Each side is ticked on its own (a side-scroller
  may limit only the bottom and the left). For rooms the camera stays in, use
  [CameraZone nodes](/manual/camera-tools/#rooms-camera-zones).
- **`e.Camera2D_ZoomTo(camera, zoom, seconds)`** eases the zoom: below 1 shows more of the world.
- **`e.Camera2D_Shake(camera, strength, seconds)`** shakes by up to `strength` pixels, fading out;
  with no strength or duration it uses the camera's Shake settings.
- **`e.Game_HitStop(game, seconds)`** freezes the game in real time. A longer one extends a running
  one; a shorter one doesn't cut it, so many hits at once don't stack into a long freeze.

## Try it

- A box the player moves in without moving the camera: the camera's **Dead zone X / Y** (120,
  60). Or from a script, with the rest of the settings:

  ```odin
  // Given: camera: ^e.Camera2D, player: ^e.Node
  camera.follow.mode = .Exponential
  camera.follow.smoothing = 4
  camera.follow.deadzone = {120, 60}
  e.Camera2D_SetLimit(camera, .Bottom, 720)
  e.Camera2D_SetFollowTarget(camera, player)
  ```

- Slow motion for a finishing blow: `e.Game_SetTimeScale(self.game, 0.3)`, and `1` to go back.
- A camera that leads more upward when falling: add `velocity.y` to the target the same way.
- Pan to show the player a door that opened, then come back:
  `e.Camera2D_MoveTo(camera, door_position, 1.2)`. While it pans, following waits.
- With an LDtk level, take the limits from the level instead of typing them, as `hero.odin` does:
  `e.Camera2D_SetBounds(camera, {0, 0}, level.views[0].level.size)` with the scene's LDtkLevel
  node.
- Follow from your own code instead (a point between two players, say): leave the Target empty
  and call `e.Camera2D_Follow(camera, point, deltaTime)` every frame; it uses the same settings.
